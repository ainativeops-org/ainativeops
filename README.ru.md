# AiNativeOps

**Community Interest Project** · открытая референсная модель · **альфа 0.2** · [English version](README.md)

AiNativeOps описывает эксплуатацию, в которой ИИ-агенты создают, изменяют и проверяют целевую систему на всём жизненном цикле, от данных и моделей до кода и выпуска. Решение о выпуске принимает контур контроля. В нём работают детерминированные проверки, ИИ-контролёр и ответственный человек на рубежах G0–G9. Каждый ИИ, который создаёт или оценивает систему, входит в область анализа.

Модель описывает классы сервисов, их типовое размещение по средам и процессы, в которых они участвуют. У каждого элемента карты есть источники трёх типов: стандарты, опубликованные практики и примеры реализации. Названия классов называют функции, поэтому класс `RM-ACT-02 Точка исполнения политики (PEP)` может реализовать любой продукт.

> Статус: **альфа-версия 0.2** ([заметки к выпуску](docs/releases/v0.2.0-alpha.md)). До версии 1.0 состав классов, их названия и идентификаторы могут меняться в любом выпуске. Не ссылайтесь на RM-ключи альфа-версии в нормативных документах и договорах. Замечания и предложения принимаются.

## Карта

**[ainativeops.org](https://ainativeops.org)** · интерактивная карта собрана в один HTML-файл и содержит три вида.

| Вид | Что показывает | Объём |
|---|---|---|
| Архитектура | Метаконвейер по уровням: бизнес, методология, Ops (DataOps, MLOps, DevOps, SecOps) и технологии. Рубежи G0–G9 связывают методологию с конвейерами. | 91 элемент |
| Инфраструктура | Типовое размещение классов по зонам: внешний контур, периметр, AI Safety Core, EXP / EVAL / PROD, платформа данных, CI/CD, Observability, доверенные сервисы. | 87 элементов, 106 связей, 94 зависимости |
| Стек платформы | Классы сервисов по слоям от «01 · Оборудование» до «07 · Продукты» и колонки CI/CD, Observability, кибербезопасности и AI Safety Core. | 106 классов, 130 зависимостей |

Двадцать процессов проводят маршрут через виды, например «Защищённая работа сотрудника с ИИ-помощником» (`INF-01`) или «Расследование и устранение инцидента безопасности ИИ» (`FLOW-INCIDENT`). Карточка процесса показывает схему с развилками и исходами, шаг схемы открывает описание и компоненты. Карточка элемента перечисляет источники: сначала стандарты, последними примеры реализации.

Карта работает на русском и английском языках. В ней есть поиск по названию и RM-идентификатору, мини-карта и пошаговый показ. Ссылка сохраняет вид, язык, процесс и размещение: `?view=stack&lang=ru&mapProcess=INF-01&mapVariant=external`.

## Основные положения

- **ИИ-инженер и ИИ-контролёр.** Один ИИ создаёт систему, другой её оценивает. Оценка контролёра служит свидетельством для рубежа, решение принимает защищённый механизм правил.
- **Правило рекурсивного замыкания.** В область анализа входит каждый ИИ, который создаёт, изменяет или оценивает систему. Вопрос повторяют для каждого добавленного компонента, пока состав не перестанет меняться.
- **Основание доверия.** Проверяемый механизм, который защищён от изменения тем, кого он ограничивает. Он завершает рекурсию «кто проверит проверяющего».
- **AI Safety Core.** Группа классов, которая исполняет контроль. В неё входят безопасность исполнения (PDP / PEP), безопасность инференса (guardrails), безопасность данных, confidential computing и доверенные сервисы.
- **Устойчивые идентификаторы.** У каждого класса есть ключ вида `RM-AGT-04`. После версии 1.0 ключ не меняется и не переиспользуется.

## Структура репозитория

```
model/
  stack/
    _layers.yaml          порядок слоёв, размещение на карте, категории цвета
    hardware.yaml …       файл на слой; классы слоя в порядке отрисовки
  infrastructure/
    zones.yaml            зоны и строки элементов в них
    elements.yaml         элементы; элемент с class: без своего текста берёт текст класса
    relations.yaml        [от, к, тип]
  architecture/
    _layout.yaml          уровни, группы с координатами, потоки
    business.yaml …       файл на уровень
  scenarios/
    process-inf-01-local.yaml …   маршрут на файл: порядок, название, шаги во всех видах
  processes/
    _groups.yaml          группы процессов в порядке показа
    flows/INF-01.yaml …   процесс: владелец, запуск, результат, этапы, маршруты, узлы и переходы схемы
    parts/INF-01.yaml …   этапы и варианты процесса; _shared.yaml для общих частей
  dependencies/           зависимости между классами и между элементами инфраструктуры
  sources/
    registry.yaml         источники: тип, название, адрес, раздел, пояснение, дата проверки
    bindings.yaml         источники каждого элемента и зоны
  profiles.yaml           параметры, от которых зависит маршрут процесса, например размещение модели
site/                     шаблон, стили и код карты (раскладка, трассировка линий, процессы, карточки)
tools/
  validate.py             проверки модели, которые запускает CI
  build.py                сборка dist/index.html
  build_versions.py       сборка прошлых выпусков из тегов в dist/<папка>/
  workflows.py            раскладка и SVG схем процессов
  check_layout.py         проверка в браузере: линии, маршруты процессов, английский текст
backlog/                  задел на 0.3, который карта пока не использует; не собирается
project.yaml              версия, лицензия, адрес репозитория
```

Файл на слой позволяет назначить каждому слою сопровождающего через `.github/CODEOWNERS`. Два pull request в разные слои не правят один и тот же файл.

Каждое название и описание хранится на двух языках. У классов и элементов это `{ru, en}`, у текстов процессов пара `[ru, en]`. Пример приведён в [README.md](README.md#repository-layout).

## Сборка

Сборке нужен Python 3.10+.

```bash
pip install -r requirements.txt
python tools/validate.py
python tools/build.py          # создаёт dist/index.html
```

Откройте `dist/index.html` в браузере. Если установлен Playwright, сборка встраивает геометрию линий и работает проверка раскладки:

```bash
pip install playwright && python -m playwright install chromium
python tools/build.py
python tools/check_layout.py
```

Без Playwright карта работает так же и прокладывает линии в браузере. Ключ `python tools/build.py --no-routes` пропускает расчёт геометрии намеренно.

## Участие

Проще всего нажать **«Предложить правку»** в панели элемента на карте. Кнопка откроет форму issue, в которой уже указаны элемент и его текущее описание. Инженеры могут править YAML напрямую и открыть pull request. Порядок описан в [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md) и [GOVERNANCE.md](GOVERNANCE.md).
