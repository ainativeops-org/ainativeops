# Как предложить изменение

[English version](CONTRIBUTING.md)

AiNativeOps развивается как Community Interest Project. Изменение попадает в модель после рецензии сопровождающего затронутого слоя. Предложить его можно двумя способами.

## 1. С карты, без Git

1. Откройте элемент на карте и нажмите **«Предложить правку»**.
2. GitHub откроет форму issue, в которой уже указаны элемент, вид и текущее описание.
3. Опишите изменение и причину. Если есть источник или практический случай, укажите его.

Сопровождающий отвечает в issue. Принятое предложение переносит в pull request сопровождающий или автор.

## 2. Pull request с правкой YAML

1. Сделайте форк репозитория и измените файлы в `model/`. Классы слоя лежат в `model/stack/<слой>.yaml`.
2. Запустите проверки:
   ```bash
   pip install -r requirements.txt
   python tools/validate.py
   python tools/build.py
   ```
3. Откройте pull request. CI повторит проверки, отрисует карту в браузере и приложит собранную страницу как артефакт.

### Что хранится в файлах модели

| Путь | Содержимое | Ключ |
|---|---|---|
| `model/stack/<слой>.yaml` | классы сервисов одного слоя; `_layers.yaml` задаёт порядок слоёв и цвета | `RM-ABC-01` |
| `model/infrastructure/` | `zones.yaml` со строками элементов, `elements.yaml`, `relations.yaml` | slug строчными латинскими буквами |
| `model/architecture/` | `_layout.yaml` с уровнями, группами и потоками; файл уровня с его элементами | короткий id, рубежи `g0`–`g9` |
| `model/scenarios/<id>.yaml` | один сценарий: порядок, название, маршруты по видам | имя файла |

### Правила изменения

- **Два языка.** У каждого `name` и `desc` есть `ru` и `en`. Если вы пишете на одном языке, отметьте это в pull request, второй язык добавит сопровождающий.
- **Без вендоров в названиях классов.** Класс называет функцию, например `LLM Gateway`. Продукты обсуждают в pull request или в примерах. Kubernetes, Jupyter и OpenTelemetry приняты как отраслевые стандарты.
- **Один термин на понятие.** Если описание упоминает другой класс, используйте его название.
- **Новый класс** добавляют в конец файла слоя со следующим свободным номером. CI отклонит ключ, префикс которого не совпадает с остальными ключами слоя.
- **Удаление класса.** Укажите `status: deprecated` и `replacedBy: RM-…`. Выпущенный ключ не удаляют и не переиспользуют.
- **Элемент инфраструктуры** ссылается на класс через `class: RM-…`. Поля `name` и `desc` добавляют, только если элемент отличается от класса. Пример: «Зеркало пакетов» реализует класс `Artifact Registry`.
- **Связи** имеют тип `flow`, `serving`, `triggering` или `access`.

### Стиль текста

Каждое предложение сообщает факт, решение или условие. Подлежащее действует, сказуемое называет действие: «PEP блокирует вызов», без конструкций вида «осуществляется блокирование вызова». Описание занимает два-три предложения и содержит конкретику: число, название или ограничение.

## Лицензия вкладов

Участник соглашается, что его вклад в `model/` распространяется по CC BY 4.0, а вклад в `site/` и `tools/` по MIT. Подписывайте коммиты (`git commit -s`), это подтверждает [Developer Certificate of Origin](https://developercertificate.org/).
